# Contributing to C Market

## Development principles

- Keep all user-facing copy in clear English for the hackathon submission.
- Prefer mobile-first UX decisions.
- Make transaction state explicit.
- Never hide the network, destination, amount, or fee context.
- Do not add investment guarantees or profit claims.
- Keep Devnet and production configuration separate.
- Never commit secrets.

## Pull requests

Every change should explain:

- What user or judging requirement it addresses.
- How it was tested.
- Whether it changes transaction behavior.
- Whether screenshots, demo instructions, or compliance documents need updates.

Before opening a pull request:

- Run the available type checks and tests.
- Review the diff for secrets.
- Confirm the README remains accurate.
- Update the relevant documentation.
